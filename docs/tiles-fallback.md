# План Б: если тайлы OpenFreeMap перестанут работать

Документ на случай, когда карта перестанет рисоваться или условия OpenFreeMap изменятся.
Составлен 12.09.2026. Актуальные факты: OpenFreeMap — бесплатный публичный инстанс (донаты,
без SLA), данные OpenStreetMap (ODbL).

## Где именно мы зависим от OpenFreeMap (5 точек)

Все тайлы берутся из одного домена `tiles.openfreemap.org`. Точки зависимости:

| № | Файл | Поле | Текущее значение |
|---|------|------|------------------|
| 1 | `map-style-brand.json` | `sources.openmaptiles.url` | `https://tiles.openfreemap.org/planet` |
| 2 | `map-style-brand.json` | `sources.ne2_shaded.tiles[0]` | `https://tiles.openfreemap.org/natural_earth/ne2sr/{z}/{x}/{y}.png` |
| 3 | `map-style-brand.json` | `glyphs` | `https://tiles.openfreemap.org/fonts/{fontstack}/{range}.pbf` |
| 4 | `map-style-brand.json` | `sprite` | `https://tiles.openfreemap.org/sprites/ofm_f384/ofm` |
| 5 | `src/config.ts` | `mapAttribution` | ссылки на openfreemap.org + openstreetmap.org/copyright |

Отдельно, не тайлы: геокодер — `src/config.ts` → `nominatimUrl` (`nominatim.openstreetmap.org`).
Правила OSM: не больше 1 запроса в секунду, обязательный User-Agent, массовый геокодинг запрещён.

Проверить, что именно упало, можно одной командой:

```bash
curl -s -o /dev/null -w "%{http_code} style\n" https://tiles.openfreemap.org/styles/liberty
curl -s -o /dev/null -w "%{http_code} planet\n" https://tiles.openfreemap.org/planet
curl -s -o /dev/null -w "%{http_code} font\n" https://tiles.openfreemap.org/fonts/Noto%20Sans%20Regular/0-255.pbf
```

Важная деталь: шаблон тайлов версионный и берётся из TileJSON.
`https://tiles.openfreemap.org/planet` отдаёт, например,
`.../planet/20260906_080001_pt/{z}/{x}/{y}.pbf` — дата внутри пути меняется при обновлении
датасета. В `map-style-brand.json` указан короткий адрес `/planet`, MapLibre сам резолвит
TileJSON, поэтому менять ничего не нужно. Но в скриптах и проверках нельзя хардкодить
тайл-путь без версии: пустой ответ легко принять за сбой.

Автоматический контроль: cron-задача **«Сторож тайлов карты (events-map)»** (каждый день в 09:00,
молчит при норме). Скрипт: `~/.hermes/scripts/tiles_watchdog.py` (копия —
`profiles/lexa/scripts/tiles_watchdog.py`). Проверяет стиль, TileJSON, реальный тайл Убуда
z12, шрифты, спрайт и Nominatim; при сбое пишет в чат, 1-го числа месяца напоминает про этот план.

Если стиль отвечает, а `planet` нет — проблема только в тайлах, стиль можно оставить.

## Резерв №0 — уже встроен в приложение (сделано 12.09.2026)

`src/lib/mapStyle.ts` → `attachTilesFallback(map)` подключается на всех трёх картах (главная,
форма события, админка). Логика:

- если браузер получил ошибку загрузки тайлов/спрайта/шрифтов от OpenFreeMap, либо источник
  `openmaptiles` не поднялся за 15 секунд — карта сама переключается на аварийный растровый
  стиль OpenStreetMap (`https://tile.openstreetmap.org/{z}/{x}/{y}.png`);
- сайт остаётся полностью рабочим: маркеры, кластеры, фильтры, карточки. Теряется только
  брендовое оформление карты;
- проверено принудительной блокировкой домена openfreemap в браузере: переключение сработало,
  на экране остались все 385 маркеров.

Смена источника без пересборки стиля — переменные окружения при сборке:
`VITE_TILES_URL` (векторный источник), `VITE_TILES_RASTER_URL` (рельеф), `VITE_GLYPHS_URL`
(шрифты), `VITE_SPRITE_URL` (иконки). Стиль и слои остаются наши.

Проверочный скрипт: `scripts/check-map-fallback.mjs` (нормальный режим и режим с блокировкой
OpenFreeMap).

## Что нужно для полноценного резерва в R2 (вариант B)

**Решение Дмитрия от 12.09.2026: пока живём на встроенном резерве №0, R2 не заводим.**
Пересматриваем, когда сработает любой из триггеров:
1) сторож тайлов ругается два дня подряд (значит резерв №0 становится основным);
2) понадобится брендовая карта при высокой нагрузке (публичный инстанс перестанет быть уместным);
3) появится аккаунт Cloudflare с привязанной картой — тогда нарезка и заливка в R2 займут вечер.

Инструкция на этот случай (актуальна, когда дойдём):

1. Аккаунт Cloudflare с привязанным платёжным методом — R2 требует карту даже на бесплатном уровне.
2. Нарезка тайлов наших регионов (planetiler/tilemaker в Docker; Java локально не нужна).
3. Загрузка в бакет R2 (S3-совместимый API, egress бесплатный) и подстановка адреса через
   `VITE_TILES_URL` при сборке.

Пока этого нет — работает резерв №0, а запас прочности даёт то, что провайдер меняется
переменной окружения за одну сборку.

## Вариант A — платный провайдер за 15 минут (аварийный)

Самый быстрый способ вернуть карту: подставить чужой тайл-сервер.

- **MapTiler** — бесплатный уровень ~100 тыс. тайлов/мес, далее от ~$25/мес. Свой стиль
  делается из их шаблона, наш брендовый JSON придётся пересобрать на их source.
- **Stadia Maps** — бесплатный уровень для малого трафика, далее от ~$20/мес.
- **Mapbox** — ~50 тыс. загрузок карты бесплатно, далее платно; самый дорогой и самый
  «привычный» вариант.

Плюсы: включается за вечер, есть поддержка и SLA. Минусы: платно при росте, стиль надо
пересобирать под новый источник.

## Вариант B — свои тайлы (рекомендуемый для коммерции)

Векторные тайлы — это статические файлы, их можно один раз нарезать и раздавать почти
бесплатно.

1. Нарезать тайлы для наших регионов (Бали, Вьетнам) генератором `planetiler` или `tilemaker`
   из свежего дампа OSM. Для трёх регионов это единицы гигабайт вместо сотен.
2. Положить в **Cloudflare R2**: хранение $0.015 за ГБ в месяц, **исходящий трафик
   бесплатный** (главное отличие от S3), запросы ~$0.36 за миллион.
   Оценка для нас: 3 ГБ тайлов ≈ $0.05/мес хранения + копейки за запросы.
3. Подменить 4 поля в `map-style-brand.json` на адреса R2 — стиль, слои и бренд остаются
   наши, ничего пересобирать не нужно.
4. Обновлять раз в 2–4 недели (скрипт нарезки + загрузка).

Плюсы: независимость, копеечная стоимость, наш брендовый стиль сохраняется. Минусы: нужен
разовый вечер на настройку нарезки.

## Вариант C — свой сервер OpenFreeMap

У них открыт весь продовый сетап: поднимается на своём VPS. Полная планета требует
диск ~100+ ГБ и много памяти, поэтому имеет смысл только если мы решим раздавать карту
для других. Для нашего проекта перебор.

## Вариант D — гибрид, дешёвый и надёжный

Оставить OpenFreeMap основным, но вынести адрес тайлов в переменную окружения
(`VITE_TILES_URL`) и держать в R2 холодную копию тайлов наших регионов. Переезд тогда
занимает одну правку переменной и перезапуск сборки. Это то, к чему стоит прийти, когда
появится коммерческая нагрузка.

## Чек-лист переключения (любой вариант)

1. Прописать новый адрес тайлов в 4 поля `map-style-brand.json` (см. таблицу).
2. Обновить `mapAttribution` в `src/config.ts` — атрибуция OSM обязательна всегда,
   у платных провайдеров добавляется их собственная.
3. Если меняем геокодер — новый адрес в `nominatimUrl` (или свой Nominatim).
4. `npm run build` → проверить, что карта рисуется и маркеры на месте.
5. Обновить `gh-pages` (пуш сборки), подождать ~10 минут кэша GitHub Pages.
6. Проверить на телефоне: карта, кластеры, карточка события.

## Триггер для переезда

- Сторож тайлов выдаёт ошибки два дня подряд.
- OpenFreeMap публикует изменение условий или ограничения.
- Наш трафик выходит за пределы разумной нагрузки на публичный инстанс
  (ориентир — сотни тысяч просмотров карты в месяц).
- Карта нужна в офлайне или понадобились платные функции (спутник, маршруты).
